Agent Properties

Memory · Planning · Tool Calling

🧠

Personality Profile: Cached after extraction, reused for all simulations.
Cross-scenario: One personality model, unlimited what-ifs.
🗺️
Planning
3-Path Strategy: Given personality + scenario, plans 3 divergent trajectories.
Bias-aware: Injects detected cognitive biases into simulation.

🔧
Tool Calling
Extraction API: POST /personality/extract
Simulation API: POST /simulate
Streaming API: GET /simulate/stream (SSE)
Health check: GET /health reports GPU status
Agent loop: Interview (gather) then Extract (model) then Simulate (plan 3 paths) then Analyze (bias + insight). Each step is a separate LLM call with structured system prompts and JSON parsing.

Defensive Q&A

Anticipating Judge Questions

Q: How is this different from just asking ChatGPT "what if I...?"
ChatGPT doesn't know you. It gives generic advice based on your prompt. Hello E World builds a 16-dimension personality model from your conversation — your risk tolerance, decision style, cognitive biases — then uses that model to simulate paths that are true to who you are. Same scenario, different person → different paths.
Q: Is the personality model scientifically validated?
No. We're transparent about this. It's an LLM interpretation of conversation patterns, not a clinical assessment. But it doesn't need to be clinical — it needs to be useful. The value is in making abstract "what-ifs" feel concrete and personal, not in diagnosing personality disorders.
Q: Why Qwen2.5-14B and not a larger model?
W7900 has 48GB VRAM. Qwen2.5-14B in bf16 takes ~28GB, leaving 20GB for KV cache and context. 32B would need 64GB — doesn't fit. 7B is too small for nuanced personality analysis. 14B is the sweet spot for this hardware.
Q: Where's the "agent" part? This seems like a chatbot.
The agent loop is: Interview (gather information adaptively) then Extract (build structured model via tool call) then Simulate (plan 3 divergent paths via tool call) then Analyze (bias detection + insight synthesis). Each step uses memory from previous steps and makes independent LLM calls with different system prompts. It's not a single-turn chat — it's a multi-stage pipeline.
Q: How do you verify it's actually running on GPU?
rocm-smi shows the W7900. torch.cuda.is_available() = True. torch.cuda.get_device_name(0) = "AMD Radeon Graphics". vLLM boot log shows VRAM allocation. We also have GET /health endpoint that reports GPU status at runtime.
